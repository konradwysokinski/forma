# Forma — CLAUDE.md

Open-source, local-first view of your running **fitness, fatigue and form**, fed by Strava. A calm, easy-to-scan alternative to Intervals.icu. Built by Konrad (Design Team Lead, product designer) as a portfolio piece showing vibe coding: the code should be clean, the UI calm and polished.

It does one thing well: **am I getting fitter, how tired am I, and is today a day for a hard run.** Not a training planner, not a social feed.

Sister project: **Kilometr** (`../Kilometr`, km on shoes and bikes). Forma copied its stack, tokens, Strava sign-in, storage and i18n, then went its own way. The two apps share no code and no storage; never import across the repos and never edit Kilometr from here.

Design references:
- Form screen mockup (agreed): https://claude.ai/artifact/CAcdFArU8CWHaPhattXZYz, local copy `design/Form.dc.html` (drawn in Kilometr's frame, so its sidebar still says Kilometr). Use it as the visual reference (layout, spacing, copy, states), not as code.
- Kilometr's design system: `../Kilometr/CLAUDE.md` §4 and its `/design-system` page. Forma follows it; differences are in §4 below.

## 1. Product decisions

- **Local-first.** Data stays in the user's browser (IndexedDB, `src/lib/db.ts`). No accounts. The only server code is the Strava token exchange (`server/stravaToken.ts`, served as `api/strava/token.ts` on Vercel and as Vite middleware in dev), because the Client Secret must not reach the browser; it stores nothing.
- **Data sources are swappable modules** feeding one `Activity[]` (`src/domain/types.ts`); the model never knows where data came from. Konrad, 2026-11-26: **COROS is meant to be the primary source** (he wears COROS), Strava a fallback for other watches, `.fit` import later. Next step is a COROS spike on Konrad's account before building on it, because COROS's self-service access is unusual:
  - No plain REST API for individual developers: apps connect to COROS's **MCP server** (`https://mcp.coros.com/mcp`; regional `mcpeu.` / `mcpus.` / `mcpcn.`) with OAuth 2.0, single user, no approval needed. Partner API (REST, webhooks) needs a company application (api@coros.com).
  - **Spike result (2026-11-26, Konrad's account):** it works from the browser alone. Discovery at `mcp.coros.com/.well-known/oauth-protected-resource/mcp` points to the region (`mcpeu.coros.com` for Konrad); dynamic client registration (`/connect/register`, `token_endpoint_auth_method: none`) + PKCE S256 + `resource` parameter; scope `openid mcp.tools offline_access`; CORS allows `http://localhost:5174` on register, token and `/mcp` (a production origin is not tried yet). MCP is stateless: one JSON-RPC POST per call, no session header.
  - Tools return formatted text written for AI (wrapped in a JSON string inside `content[0].text`), not structured data. Parsed in `src/coros/parse.ts` (tests on invented fixtures in `fixtures.ts`), strictly: anything unknown throws `CorosFormatError` naming the line.
  - `querySportRecords` text: a header `Sport Records — <from> to <to> (N records)`, a `====` rule, then numbered records `N. <Name> — YYYY-MM-DD` with indented lines: `Location:` and `Start Coordinates:` (both optional, skipped unread), `Time Window: startTimestamp=<epoch s> | endTimestamp=…`, `Duration: m:ss|h:mm:ss | Distance: 10.98 km|979 m` (moving time; distance absent for gym and table tennis, and then the line breaks before ` | Avg HR`), `Average Pace: 5:17 /km` or `Average Speed: 28.7 km/h` ` | Avg HR: 140 bpm | Calories: …` (HR occasionally absent), `LabelId: <digits> | SportType: <code>`. No elevation. Start time = `startTimestamp` on the browser's clock.
  - `queryRestingHeartRate`: `YYYY-MM-DD: 45 bpm` lines (Forma takes the median). `queryUserInfo`: `Gender: Male|Female` among height, weight, birthday and nickname (only gender is read).
  - `querySportRecords` **does include average heart rate** (the docs' example doesn't show it). Each record: name ("Outdoor Run", "Trail Run", "Walk", "Hike", "Cycling", "Gravel Bike", "Gym Cardio", "Ping Pong"…), date, start and end timestamps, Duration (moving), Distance (km or m), pace or speed, Avg HR (absent on some), Calories, `LabelId`, `SportType` code (100 run, 102 trail run, 104 hike, 200 road bike, 203 gravel bike, 400 gym cardio, 900 walk, 1001 table tennis). Newest first, **at most 100 per call**, so sync pages by date windows (a year is roughly 6–12 calls). No per-activity call is needed for load.
  - COROS's own load, `queryTrainingLoadAssessment`: per day Short-Term Load (fatigue-like), Long-Term Load (fitness-like), Load Ratio and a comment (Resuming / Maintaining / Optimized …), but **only the last 31 days**, whatever `days` asks. Its ratio maps to Forma's form as 1 − ratio, though COROS's own words differ from Forma's zones (ratio 1.36 is "Optimized" there, High risk here). History curves stay Forma's own.
  - Also useful: `queryRestingHeartRate` (daily, 30 days: a real resting HR for the load formula), `queryUserInfo` (age, sex: picks the TRIMP constants), `queryFitnessAssessmentOverview` (VO2max, threshold pace, 5 km / 10 km / half / marathon predictions), `queryRecoveryStatus` (current only). No max heart rate field.
  - `querySleepOverview` (spike 2026-11-26): **one call returns every day of a 420-day range** (oldest first, ~20 s, ~120 KB), no 100-record cap. Text: `Sleep Overview`, a rule, a `Note:` line, then one block per wake-up day: the date alone on a line, then `Key: value` lines. Forma reads `Sleep Score` (`-1` = none), `Daily Sleep: 7h 12min (incl. naps)` (or `45min`), and on older days without Daily Sleep (before ~Apr–Aug 2026) `Main Sleep:` / `Main Sleep (asleep):` + `Naps Total:` / `Naps Total (asleep):` (sometimes suffixed `(includes legacy reported durations)`). Stage ratios, awake time and count, windows, `Sleep metrics scope` and periods incl. awake are skipped by name. A day can be only `Sleep detail for this day is not available yet.` (no night); an empty range says `No sleep overview data found.` Daily Sleep often differs from main + naps by up to an hour, so it wins when present. Parsed in `parseSleep`.
  - Never store or commit real responses: they hold names, birthdays and start coordinates.
  - Tokens: access 30 days, refresh 180 days (renewed on each refresh).
  - Docs: github.com/coroslab/COROS-MCP (`docs/en/tools.md`, `faq.md`). Never use community COROS servers built on reverse-engineered endpoints.
  - Any COROS client secret follows the same rule as Strava's: server-side only, set by Konrad, never typed or read by Claude.
- **Own Strava API app** (Konrad, 2026-11-26), not Kilometr's: its own Client ID, callback domain and request limit (100 per 15 min, 1 000 a day, shared by every Forma user). Konrad creates it on strava.com/settings/api. Client ID goes in `STRAVA_CLIENT_ID` and `VITE_STRAVA_CLIENT_ID`, the secret in `STRAVA_CLIENT_SECRET` (`.env.local` locally, Vercel env in production; see `.env.example`). Claude never types, reads or asks for the secret or tokens, and never reads `.env.local`.
- **Platform:** Vite + React 19 + TypeScript + CSS modules, Vercel later (not set up yet), runs on localhost (port 5174, Kilometr has 5173).
- **COROS sync** (`src/coros/`, built 2026-11-26): `oauth.ts` (sign-in; tokens and the registered client in localStorage), `mcp.ts` (JSON-RPC over POST), `parse.ts`, `client.ts` (the three tools Forma calls), `sync.ts` (pure, tested), `store.ts` (IndexedDB key `coros`: activities, last sync, resting HR, sex).
  - First sync: 420 days back (42 for fitness to settle + the Year chart) in 31-day windows, newest first; a window that comes back with 100 records is halved until it fits. About 14 calls; ~720 activities for Konrad. Later syncs re-fetch from 3 days before the newest stored activity and replace those days (so deletions in COROS carry over).
  - Sleep (`syncSleep`): **one call per sync**, the whole 420 days the first time, then from 3 days before the newest stored night (a night's score can arrive late), replacing those days. Stored in the `coros` record as `sleep: { date, minutes, score }[]` by wake-up date; nothing else from sleep is kept. Data saved before sleep existed (no `sleep` field) syncs at once on opening, not after the hour (`needsSync`), and gets the full sleep history then. A sleep error fails the sync like any other.
  - Sync runs on opening Forma and on coming back to the tab when data is over an hour old, and on clicking the sidebar status. Sports: codes 100–103 run, 2xx ride, everything else `other` (all count as load).
  - Athlete: resting HR = median of COROS's last 30 days; sex from the profile; max HR from `estimateAthlete`. Settings can replace max and rest (see §2).
- **Data budget:** everything comes from the source's activity list: moving time, average heart rate, distance, sport type, local start; plus one sleep call per sync. No per-activity requests (COROS: `getActivityDetail`; Strava: streams and best efforts) unless Konrad agrees.
- **Languages:** English and Polish. First visit follows the browser; the choice is remembered (`forma.locale`). Switched in Settings → General (and EN | PL on Start).
- **Theme:** Light (default), Dark or System, in Settings → General, remembered as `forma.theme`. An inline script in `index.html` applies it before the first paint.
- **Status now:** the Form screen runs on the athlete's COROS data (or on the sample, `src/data/sample.ts`, pinned to 25 Nov 2026, when chosen on Start). App state (source, sync, data) is in `src/app/AppProvider.tsx`. Strava sign-in (`src/strava/auth.ts`) and mapping (`src/strava/mapping.ts`) exist but are not wired in.

## 2. The model

All in `src/domain/`, pure and tested.

- **Load per activity** (`load.ts`): Banister TRIMP from moving time and average heart rate. `minutes × HRr × 0.64 × e^(1.92 × HRr)` (women 0.86, 1.67), `HRr = (avg − rest) / (max − rest)`. Without heart rate: the same time at an easy effort (HRr 0.55). Max and resting heart rate are estimated (`estimateAthlete`: hardest average ÷ 0.92, clamped 170–210; rest 50; COROS's median when connected). Settings → Heart rate can set either (`src/domain/settings.ts`, `athleteWith`; stored as `forma.training` in localStorage; rest must stay 40+ below max). Daily load = sum over the day's activities, all sports.
- **Fitness** (CTL): `fitness += (load − fitness) / 42` per day. **Fatigue** (ATL): the same over 7 days. Both start at the average daily load of the first 42 days of history (`startingLoad`), because history never starts from zero training.
- **Form** = (fitness − fatigue) / fitness × 100, from **yesterday's** values, so today's run doesn't change today's form. Not shown for the first 7 days of history.
- **Zones** (`training.ts`): Transition above +20%, Fresh +5 to +20, Grey zone −10 to +5, Optimal −30 to −10, High risk below −30. Boundaries belong to the zone below (exactly +5% is Grey zone).
- **Records** (`records.ts`): within the screen's period (Forma only holds ~14 months, so no lifetime records). 5 km, 10 km, half marathon, marathon from whole runs of that distance up to 5% longer, time scaled to the exact distance; longest run; each with the run's average heart rate. "New" for 30 days. (No best efforts inside longer runs: those need a request per activity.)
- **Easy-pace heart rate** (`easyHr.ts`): per month, time-weighted average heart rate of runs averaging a pace in `Dataset.easyPace` (default 5:30–6:00 /km, editable in Settings → Heart rate). The KPI compares the latest month with two months before.
- **Screen summary** (`formSummary.ts`): one call computes everything the Form screen shows for a period (6 weeks, 3 months, 6 months, year). The screen's title is just "Form"; the line under it is today's zone in words plus fitness against last month's average ("Holding steady, less fit than in October.").

## 4. Design system

Forma uses Kilometr's design system (`../Kilometr/CLAUDE.md` §4): the same ground, type (Inter 400/500/600, Instrument Serif only for the wordmark "Forma"), spacing, radii, shadows, components (KPI tile, chart card, segmented control, chips) and content rules. Tokens live in `src/styles/tokens.css`.

What differs:
- **No gear colours.** Forma has no gear, so `--gear-*` are gone.
- **Compact chart card** (Konrad, 2026-11-26; the airier version is commit 7e3eb27): the fitness key (names only, meaning as title) sits in the card header; fitness 200px, form 110px, sleep 56px, rows 10px apart; the zone legend (name, range, 11px note) sits under all the charts. KPI tiles are slimmer: padding 16/18, label 13, value 32/38, line 12/16; the easy-pace tile is "Easy-pace HR" / "Tętno spokojne".
- **Card titles 16/22 (500) with a 12/16 muted note** (Konrad, 2026-11-26), quieter than Kilometr's 18/13; sub-titles inside a card (the Form row) 14/20.
- **Brand colour is deep navy**, not Kilometr's moss (Konrad, 2026-11-26): `--accent` #1F3A6E (hover #162B54, soft #E7ECF6; dark #9FB6E6 / #BCCDF0 / #1E2A40) for primary buttons, links, focus ring, switches, the new-record chip and the sync dot. Darker and greyer than `--fitness` on purpose, so it never reads as a chart colour. Green stays only in the Optimal zone.
- **Warm ground and sidebar** (Konrad, 2026-11-26): the ground behind the panel and sidebar is a warm beige-grey (`--canvas` #F3F1EC, gradient #F4F2ED → #E9E5DD), warmer than Kilometr's grey. The sidebar has its own `--sidebar-*` set (`--sidebar-bg`, `-ink`, `-ink-muted`, `-hover`, `-selected`, `-accent`, `-accent-soft`) that `.sidebar` maps onto `--ink`, `--hover` and so on, so its character can change in one place. A navy sidebar (#13234A, light text) was tried and set aside as too loud; it may come back.
- **Training colours are their own tokens** and are used for nothing else:
  - `--fitness` (#2563EB, line, gradient 18% → 0) and `--fitness-ink`
  - `--fatigue` (#8B5CF6, thinner line) and `--fatigue-ink`
  - `--load` (#E3E5E9, daily load bars, kept quiet behind the lines)
  - `--heart` (#D7263D, not the High-risk red) and `--heart-ink`: heart rate only (the easy-pace line, its gradient and labels); bpm in the Records table stays muted so it never reads as an error
  - Sports on the Weeks calendar only: `--sport-run` (rose #E0457B) and `--sport-ride` (tangerine #F2602C), each with `-ink`, as pastel blocks; `--sport-other` (the warm ground) for the quiet line. Picked from Kilometr's Focus-like hues that mean nothing else here (teal is `--sleep`).
  - `--sleep` (teal #0E95A6, 3.6:1 on the panel; dark #3FC1D0): sleep only (the night bars, the toggle's square, the tooltip key). Darker than the mockup's #0EA5B7 so a full bar passes 3:1; clear of `--fitness` blue and the Optimal green
  - Zones, each with `-ink` (text) and `-tint` (background band): `--zone-transition` (sun #E5A500), `--zone-fresh` (cobalt #2563EB), `--zone-grey` (granite #8A9099), `--zone-optimal` (forest #16A05A), `--zone-risk` (red #E5484D).
  - Zone chip: 12% of the zone colour (`color-mix`) with the zone's ink.
  - Dark values for all of them are in `tokens.css`.
- Colour is never the only identifier: every zone colour sits next to its name; the form bars have the zone legend beside them; the chart has an `aria-label` sentence.
- **Period switch:** the "box" size of `Segmented` (40px, 1px `--line`, radius 12, selected `--selected` fill, 500).
- **New-record chip:** `--accent-soft` with `--accent` text.

Charts are hand-drawn SVG (`src/components/*Chart.tsx`), sized to their container with `useWidth`, sharing x positions (`chartAxis.ts`) so the fitness chart and the form bars line up day for day.

### Content rules

- Plain, short, sentence case; one line under every number saying what it means ("Average load, last 42 days").
- Polish: same tone, real plural forms, decimal comma, locative months with the right preposition ("w październiku", "we wrześniu"), no gendered adjectives about the athlete (zone names are nouns: "Świeżość", "Szara strefa").
- No motivational fluff, no emoji.

### Accessibility

Real buttons and lists; the period and language switches are `radiogroup`s with arrow keys; `aria-label` on every chart describing what it shows; text contrast ≥ 4.5:1; visible focus ring in `--accent`.
